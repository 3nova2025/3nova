Preparación para el acceso
Si necesitas usar la API, por favor inicia sesión para completar la aplicación de la clave API y la configuración, y luego desarrolla y opera según los detalles de este documento.

Puedes hacer clic aquí para crear una clave API.

Por favor, recuerda la siguiente información después de haber creado con éxito la clave API:

APIKey: Identidad para transacciones API, generada por algoritmo aleatorio.
SecretKey: clave privada, generada aleatoriamente por el sistema, utilizada para la generación de firmas.
Riesgos: Estas dos claves están estrechamente relacionadas con la seguridad de tu cuenta, por favor ten en cuenta que no las reveles a otros en ningún momento. Cualquier fuga de estas dos llaves puede causar la pérdida de tus activos. Si encuentras alguna filtración de APIKey, por favor elimina el APIKey lo antes posible.

Tipo de interfaz
Público
Interfaz privada
Interfaz Pública
La interfaz pública puede utilizarse para obtener información de configuración y datos de mercado. Las solicitudes públicas pueden invocarse sin autenticación.

Interfaz privada
La interfaz privada puede utilizarse para la gestión de pedidos y de cuentas. Cada solicitud privada debe ser [firmada] (sign.md) utilizando una forma canónica de autenticación. La interfaz privada requiere autenticación usando tu APIKey.

Nombre de dominio API
Puedes hacerlo tú mismo usando el método de acceso a la API REST.

Nombre de dominio	REST API
Dominio Principal	https://fapi.bitunix.com
Validación de API
El encabezado de todas las peticiones REST debe contener las siguientes claves:

Clave API: Clave API de la solicitud
Nonce: cadena aleatoria, de 32 bits, generada por el llamador
Marca de tiempo: marca de tiempo actual, milisegundos
sign: cadena de firma (ver descripción de la firma)
Tipo de contenido: Configurado uniformemente en application/json.
Solicitud de interacción
Todas las solicitudes se basan en el protocolo Https, el Type-de Contenido en la cabecera de la solicitud POST debe establecerse en: 'application/json'.

Descripción de la solicitud de interacción
Parámetro de solicitud: encapsular el parámetro según el parámetro de solicitud de la interfaz.
Enviar parámetros de solicitud: enviar los parámetros encapsulados de la solicitud al servidor a través de GET/POST.
Respuesta del servidor: El servidor primero realiza la verificación de seguridad de parámetros sobre los datos de solicitud del usuario y devuelve los datos de respuesta en formato JSON al usuario según la lógica de negocio tras superar la verificación.
Procesamiento de datos: Procesar los datos de respuesta del servidor.
Éxito
El código de estado HTTP 200 indica una respuesta exitosa y puede contener contenido. Si la respuesta contiene contenido, se mostrará en el contenido correspondiente de retorno.

Códigos de error comunes
400 Solicitud mala - Formato de solicitud inválido
403 Prohibido - No tienes acceso al recurso solicitado.
404 No encontrado No se ha encontrado ninguna solicitud
Error interno del servidor 500 - Tuvimos un problema con el error interno del servidor; Cuerpo si fallido con mensaje de descripción de error
Consulta Código de error para más detalles.
Especificación estandarizada
Marca temporal
La marca de tiempo en la firma de la solicitud está en milisegundos y está estandarizada a tiempo UTC.

Formatos de petición
Actualmente, solo hay dos formatos de solicitud: GET y POST.

GET: Los parámetros se transfieren al servidor mediante queryString en la ruta.
POST: Los parámetros se transfieren al servidor enviando el cuerpo en formato json.

Parámetros públicos de firma de API Restful
Cabeceras:

Nombre	Tipos	Obligatorio	Descripción
API key	Cuerda	Y	Aplicación de la clave API
Nuncio	Cuerda	Y	Cadena aleatoria, 32 bits
Marca temporal	Cuerda	Y	Marca de tiempo actual, milisegundos
Signo	Cuerda	Y	Cuerda singanture
Pasos emblemáticos:

Todos los queryParams están ordenados en orden ASCII ascendente por clave, Ejemplo: String queryParams = "id1uid200"
Parámetros en cuerpo, comprimidos en una cadena, recuerda eliminar todos los espacios, Ejemplo:String body = {"uid":"2899","arr":[{"id":1,"name":"maple"},{"id":2,"name":"lily"}]}.
¡ Atención: El formato del cuerpo de la solicitud debe ser idéntico al de la cadena de firma.
Firma, necesita cifrarse dos veces
String digest = SHA256(nonce + timestamp + api-key + queryParams + body)
Signo de cadena = SHA256(digest + secretKey)
Nota: secretKey está incluido al solicitar la clave de la API. Por favor, guárdalos de forma segura y no los paséis de mano en mano.
Ejemplo emblemático
Ve:


package main

import (
	"crypto/sha256"
	"encoding/hex"
	"fmt"
)

func main() {
	nonce := "123456"
	timestamp := "20241120123045"
	apiKey := "yourApiKey"
	secretKey := "yourSecretKey"
	queryParams := "id1uid200" 
	body := "{\"uid\":\"2899\",\"arr\":[{\"id\":1,\"name\":\"maple\"},{\"id\":2,\"name\":\"lily\"}]}"

	digestInput := nonce + timestamp + apiKey + queryParams + body

	digest := sha256Hex(digestInput)

	signInput := digest + secretKey
	sign := sha256Hex(signInput)

	fmt.Println("Digest:", digest)
	fmt.Println("Sign:", sign)
}

func sha256Hex(input string) string {
	hash := sha256.Sum256([]byte(input))
	return hex.EncodeToString(hash[:])
}
Python:


import hashlib

def sha256_hex(input_string):
    return hashlib.sha256(input_string.encode('utf-8')).hexdigest()

def main():
    nonce = "123456"
    timestamp = "20241120123045"
    api_key = "yourApiKey"
    secret_key = "yourSecretKey"
    query_params = "id1uid200" 
    body = '{"uid":"2899","arr":[{"id":1,"name":"maple"},{"id":2,"name":"lily"}]}'

    digest_input = nonce + timestamp + api_key + query_params + body

    digest = sha256_hex(digest_input)

    sign_input = digest + secret_key
    sign = sha256_hex(sign_input)

    print("Digest:", digest)
    print("Sign:", sign)

if __name__ == "__main__":
    main()

**** Websocket API
WebSocket es un nuevo protocolo HTML5 que logra la transmisión de datos dúplex completo entre el cliente y el servidor, permitiendo que los datos se transfieran eficazmente en ambas direcciones. Se puede establecer una conexión entre el cliente y el servidor con un solo apretón de manos. El servidor podrá entonces enviar datos al cliente según reglas preestablecidas. Sus ventajas incluyen:

El tamaño de la cabecera de la solicitud WebSocket para la transmisión de datos entre cliente y servidor es solo de 2 bytes.
Tanto el cliente como el servidor pueden iniciar la transmisión de datos.
No es necesario crear y eliminar conexiones TCP repetidamente, ahorrando recursos en ancho de banda y servidor.

func Sign() string {
	apiKey := "your-apiKey"
	secretKey := "your-secretKey"
	nonce := "your-nonce"
	timestamp := time.Now().Unix()
	sign := sha256Hash(fmt.Sprintf("%s%d%s", nonce, timestamp, apiKey))
	sign = sha256Hash(fmt.Sprintf("%s%s", sign, secretKey))

	return sign
}

func sha256Hash(input string) string {
	hash := sha256.New()
	hash.Write([]byte(input))
	hashInBytes := hash.Sum(nil)
	hashInHex := hex.EncodeToString(hashInBytes)

	return hashInHex
}
Python


import hashlib
import time

def sign():
    api_key = "your-apiKey"
    secret_key = "your-secretKey"
    nonce = "your-nonce"
    timestamp = int(time.time())

    # First SHA-256 hash
    sign = hashlib.sha256((nonce + str(timestamp) + api_key).encode()).hexdigest()

    # Second SHA-256 hash
    sign = hashlib.sha256((sign + secret_key).encode()).hexdigest()

    return sign

Se crean órdenes de apertura/cierre
Se cumplen los pedidos de Apertura/Cierre
Se cancelan los pedidos
Parámetros de empuje
Parámetro	Tipo	Descripción
ch	Cuerda	Nombre del canal: posición
ts	Int64	Marca temporal
Datos	<Objeto>	Datos de suscripción
> evento	Cuerda	Evento, ABRIR/ACTUALIZAR/CERRAR
> PositionId	Cuerda	Identificación de posición
> margenMode	Cuerda	Modo de margen, AISLAMIENTO/CRUZ
> Modo de posición	Cuerda	Modo de posición, ONE_WAY/HEDGE
> lado	Cuerda	Dirección de posición, CORTO/LARGO
> palanca	Cuerda	Apalancamiento
> margen	Cuerda	Margen
> ctime	Cuerda	Crear tiempo
> cantidad	Cuerda	Tamaño de la posición abierta
> símbolo	Cuerda	Símbolo
> realizado PNL	Cuerda	PnL realizado (excluyendo la comisión de financiación y la comisión de transacción)
> PNL no realizado	Cuerda	PnL no realizado
> financiación	Cuerda	Cuota total de financiación durante el puesto
> tarifa	Cuerda	Comisiones de transacción deducidas: comisiones de transacción deducidas durante la posición

*** Descripción
Úsalo para datos de instantáneas, para 1 nivel de profundidad, para 5 niveles de profundidad, para 15 niveles de profundidad.booksbook1book5book15

books: Empujar los datos completos por primera vez, luego empujar todos los datos, es decir, si hay un cambio en la profundidad, los datos de profundidad que han cambiado serán impulsados.snapshot
book1: 1 nivel de profundidad se pondrá a prueba cada vez.
book5: 5 niveles de profundidad se pondrán a prueba cada vez.
book15: 15 niveles de profundidad se pondrán cada vez.

Parámetro	Tipo	Obligatorio	Descripción

> ch	Cuerda	Sí	Nombre del canal: depth_books,depth_book1,depth_book5,depth_book15
> símbolo	Cuerda	Sí	ID del producto
Ejemplo de solicitud:


{
    "op":"subscribe",
    "args":[
        {
            "symbol":"BTCUSDT",
            "ch":"depth_book1"  
        }
    ]
}

*** Descripción
Recupera los datos de los candelabros de un símbolo. Los datos se enviarán cada 500 ms.

El canal publicará una instantánea tras la suscripción exitosa, seguida de actualizaciones posteriores.

Para cambiar los intervalos de K-line sin desconectar el WebSocket, primero debes enviar un comando de "cancelar la suscripción" para cancelar la suscripción K-line anterior antes de suscribirte al nuevo intervalo. Por ejemplo, si actualmente estás suscrito a mark_kline_1min y quieres cambiar a mark_kline_15min, primero debes darte de baja de mark_kline_1min y luego suscribirte a mark_kline_15min.

Parámetros de la solicitud
Parámetro	Tipo	Obligatorio	Descripción
en	Cuerda	Sí	Operación, suscribirse cancelar suscripción
args	Lista<Objeto>	Sí	Lista de canales para solicitar suscripción
> ch	Cuerda	Sí	Nombre del canal, El canal de suscripción es: Tipode precio klineIntervalo de tiempo; Los tipos de precios incluyen precio de mercado y precio marcado;market_kline_1min,mark_kline_1min,market_kline_3min,mark_kline_3min,market_kline_5min,mark_kline_5min,market_kline_15min,mark_kline_15min,market_kline_30min,mark_kline_30min,market_kline_60min,mark_kline_60min,market_kline_2h,mark_kline_2h,market_kline_4h,mark_kline_4h,market_kline_6h,mark_kline_6h,market_kline_ 8h,mark_kline_8h,market_kline_12h,mark_kline_12h,market_kline_1day,mark_kline_1day,market_kline_3day,mark_kline_3day,market_kline_3day,market_kline_1week,mark_kline_1week,market_kline_1month,mark_ kline_1month
> símbolo	Cuerda	Sí	ID de producto: por ejemplo, ETHUSDT
Ejemplo de solicitud:


{
    "op":"subscribe",
    "args":[
        {
            "symbol":"BTCUSDT",
            "ch":"market_kline_1min" 
        }
    ]
}
